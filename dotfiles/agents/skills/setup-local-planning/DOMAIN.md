# Domain Documentation

Use the repository's domain language and architecture decisions during planning.

Before exploring, read these files when they exist:

- `GLOSSARY.md` at the repository root.
- `GLOSSARY-MAP.md` at the repository root and the relevant linked glossaries.
- Relevant ADRs under `docs/adr/`.
- Context-specific ADRs under `src/<context>/docs/adr/` in a large monorepo.

If these files do not exist, continue without warning. The `domain-modeling`
skill can create them when the work resolves a meaningful term or decision.

Use glossary terms consistently. If a proposed plan conflicts with an existing
ADR, identify the conflict instead of silently overriding the decision.
